# StarTrail 3.6 性能对照

## 方法

同一个 Android 15 / API 35 模拟器，软件 Canvas 540×960，固定北京地点、手动相机方位75°/仰角40°/FOV75°，银河、插画和名称开启，网格关闭。每轮10次预热、40次采样，每次模拟时间前进144秒。分别测 SkyScene.create、SkyMapView.setScene、SkyMapView.draw；使用 System.nanoTime 墙钟时间。用例位于 Performance36Test。

3.5 基线来自原3.5 APK搭配新增性能测试APK；3.6来自优化后的APK。原始记录：performance-v35-baseline.txt、performance-v36-optimized.txt。

|阶段|3.5 中位数 ms|3.6 中位数 ms|3.5 p95 ms|3.6 p95 ms|
|---|---:|---:|---:|---:|
|天体场景计算|1.546|2.916|3.031|4.500|
|星图数据更新|10.757|3.492|14.645|6.222|
|软件绘制|13.834|13.591|18.441|17.449|

本场景星图数据更新中位数降低约67.5%。场景计算本身没有修改，测量值反而上升，可能受调度/JIT/宿主机负载影响，未证明该段加速。绘制耗时变化较小，不能宣称整体帧率提高67.5%。本轮没有GPU帧时间、真机耗电或分配字节数测量。

## 改动与边界

- 背景星原始J2000向量预计算，时间/地点更新共用矩阵；复用输出数组且保留星等。
- 去重只在加载后的准备阶段执行，页面重建传入准备好的只读列表。
- 深空查找、标签名称与候选排序移出绘制循环；复用 PointF、RectF、地平线裁剪数组与 Path、渐变。并非零分配渲染：投影结果、太阳系渐变、部分插画/文字仍有分配。
- 播放调度间隔由40改为120ms，理论最高计算频率从25降到约8.3次/秒，实际还受任务耗时影响。依据真实经过时间推进，避免放慢模拟时间；手机姿态回调继续独立请求动画帧。快速播放可见离散步进。
- 新变换与旧标量路径作跨年代/位置/天极对照，并对完整背景星表检查两个时代与南北半球位置。
